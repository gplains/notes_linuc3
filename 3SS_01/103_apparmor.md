# 103   AppArmor による強制アクセス制御

## ライフサイクルを想定したコマンド

### 1. 導入と現状確認 (Investigation)

システムの AppArmor の動作状態を確認します。

- **`aa-status`** (外部ソース情報): 現在ロードされているプロファイルの一覧と、それらがどのモード（enforce, complain）で動作しているかを表示します。
- **`podman info`**: システム上で AppArmor が有効になっているかを確認するために使用されます。

### 2. プロファイルの生成と管理 (Profile Generation & Management)

新しいプログラムに対してセキュリティポリシーを定義します。

- **`aa-genprof <プログラムのパス>`**: 新しいプロファイルを生成するための対話型ツールです。プログラムを実行しながら、その挙動を学習してプロファイルを作成します。
- **`aa-logprof`**: システムログをスキャンし、AppArmor によって拒否された操作をプロファイルに追加すべきかユーザーに確認し、プロファイルを更新します。

### 3. プロファイルの適用と検証 (Loading & Verification)

作成または編集したプロファイルをカーネルにロードします。

- **`apparmor_parser <プロファイル名>`**: プロファイルをカーネルに読み込ませ、適用するために使用されます。
- **`apparmor_parser -v <プロファイル名>`**: プロファイルの構文を検証するために使用されます。
- **`apparmor_parser -R <プロファイル名>`** (外部ソース情報): 特定のプロファイルをカーネルから削除します。

### 4. 動作モードの切り替え (Mode Management)

プロファイルの厳格さを調整します。

- **`aa-complain <プログラムのパス>`**: プロファイルを **complain モード**（学習・デバッグモード）に設定します。このモードでは操作を拒否せず、違反イベントをログに記録するのみとなります。
- **`aa-enforce <プログラムのパス>`**: プロファイルを **enforce モード**（強制モード）に設定します。ポリシーに違反する操作は即座に拒否されます。
- **`aa-disable <プログラムのパス>`**: 特定のプログラムに対する AppArmor の制限を無効化します。

### 5. コンテナ環境での利用 (Podman)

コンテナのセキュリティを強化するために AppArmor を適用します。

- **`podman run --security-opt apparmor=<プロファイル名> <イメージ名>`** (外部ソース情報): 指定した AppArmor プロファイルを適用してコンテナを起動します。
- **`podman run --privileged`**: このフラグを付けてコンテナを実行すると、AppArmor や SELinux による隔離が無効化されます。
