## NFSv4とSambaにおけるPOSIX ACLの実装差異

### 1. NFSv4 における ACL の実装

NFSv4のACLは、従来のPOSIX ACLとは異なり、NFSv4プロトコル自体に組み込まれた**推奨属性**として定義されています。

- **プロトコルネイティブな設計**: 以前のNFSバージョンとは異なり、NFSv4はACLの処理に外部プロトコルを使用せず、プロトコル内で直接サポートします。
- **識別子のマッピング**: ACLの対象（ユーザーやグループ）を、数値のUID/GIDではなく、`user@domain` 形式の文字列として扱います。
- **マッピングプロセスの役割**: ローカルのUID/GIDとNFSv4名の変換は、サーバー側の `rpc.idmapd` デーモンや、クライアント側の `nfsidmap` プログラムが担当します。
- **POSIX ACLとの違い**: Linuxカーネルは内部的にPOSIX ACLを使用していますが、NFSv4経由でこれらをエクスポート・インポートする際は、プロトコル独自のACL形式に変換されます。

### 2. Samba における ACL の実装

Sambaは、Linux上のファイルシステムに対するアクセス制御として、**POSIX ACL**と、より詳細な**Windows ACL**の両方をサポートしています。

- **POSIX ACL による共有設定**:
    - **特徴**: Linux標準の `setfacl` などのツールで権限を管理します。
    - **制限**: Windows側から見ると、「アクセスなし」「読み取り」「書き込み」「フルコントロール」という、**粒度の粗い4つの権限**にマッピングされます。
    - **自動マッピング**: ディレクトリーの所有者は「owner」、プライマリーグループは「primary_group」としてWindows ACLへ動的にマッピングされます。また、`CREATOR OWNER` や `CREATOR GROUP` といった特殊なプリンシパルも自動で追加されます。
- **Windows ACL（高度なACL）による共有設定**:
    - **特徴**: 「サブディレクトリーとファイルの削除」や「属性の書き込み」など、**きめ細かな14種類以上の権限**を制御できます。
    - **実装**: 設定ファイル `smb.conf` で `vfs objects = acl_xattr` を有効にする必要があります。これにより、ACL情報はファイルシステムの**拡張属性 (xattr)** に保存されます。
    - **管理ツール**: Linux上からは `smbcacls` ユーティリティーを使用してACE（アクセス制御エントリー）を直接操作・表示できます。

### 主な実装差異のまとめ

| 特徴         | NFSv4 ACL             | Samba (POSIX ACL) | Samba (Windows ACL)       |
| :--------- | :-------------------- | :---------------- | :------------------------ |
| **主な保存場所** | ファイルシステム属性            | ファイルシステム (POSIX)  | 拡張属性 (xattr)              |
| **ユーザー識別** | `user@domain` 文字列     | ローカル UID/GID      | SID (Security Identifier) |
| **権限の粒度**  | 推奨属性に基づく              | 基本4種類 (Samba経由)   | 高度な14種類以上                 |
| **管理コマンド** | `nfs4_setfacl` (ソース外) | `setfacl`         | `smbcacls`                |
|            |                       |                   |                           |



## ライフサイクルを想定したコマンド

### 1. ACLs によるファイル・ディレクトリー操作 (`getfacl`, `setfacl`)

ACL は、従来の所有者・グループ・その他（DAC）よりも詳細な権限設定を可能にします。

- **設定・変更 (Create/Update)**:
    - `# setfacl -m u:<ユーザー名>:<権限> <ファイル名>` : 特定のユーザーに権限を付与します（例：`u:user1:rwx`）。
    - `# setfacl -m g:<グループ名>:<権限> <ファイル名>` : 特定のグループに権限を付与します。
    - `# setfacl -m d:u:<ユーザー名>:<権限> <ディレクトリー名>` : **デフォルト ACL** を設定し、その配下に作成されるファイルに権限を継承させます。
- **確認 (Read)**:
    - `$ getfacl <ファイル名>` : ファイルやディレクトリーに設定されている ACL エントリーを表示します。
- **削除 (Delete)**:
    - `# setfacl -x u:<ユーザー名> <ファイル名>` : 特定のエントリーのみを削除します。
    - `# setfacl -b <ファイル名>` : ファイルからすべての拡張 ACL エントリーを削除し、標準パーミッションのみに戻します。

### 2. アクセス制御に関連する拡張属性の操作 (`getfattr`, `setfattr`)

拡張属性 (xattr) は、SELinux コンテキストや Samba の高度な Windows ACL 情報を保存するために使用されます。

- **設定・変更 (Create/Update)**:
    - `# setfattr -n <属性名> -v <値> <ファイル名>` : 拡張属性を付与します。
    - （例：Samba において Windows ACL を保存する場合、`vfs objects = acl_xattr` を有効にすると、ACL 情報が拡張属性に書き込まれます。）
- **確認 (Read)**:
    - `$ getfattr -d <ファイル名>` : ファイルに設定されているすべての拡張属性を表示します。
    - `$ getfattr -n security.selinux <ファイル名>` : 特定の名前（例：SELinux ラベル）の属性を表示します。
- **削除 (Delete)**:
    - `# setfattr -x <属性名> <ファイル名>` : 特定の拡張属性を削除します。

### 3. ACLs/拡張属性の設定を考慮したコマンドの利用

標準コマンドを使用する際、ACL や拡張属性を保持したまま操作を行う必要があります。

- **ls (確認)**:
    - `$ ls -l <ファイル名>` : パーミッションの末尾に **`+`** 記号が表示されている場合、ACL が設定されていることを示します。
    - `$ ls -Z <ファイル名>` : SELinux コンテキストを表示します。
- **cp (コピー)**:
    - `# cp -p <元ファイル> <先>` : 所有者、グループ、権限、タイムスタンプを保持します。
    - `# cp -a <元ファイル> <先>` : ACL や拡張属性（xattr）を含むすべての属性を保持してコピーします（推奨）。
- **mv (移動)**:
    - `# mv <元ファイル> <先>` : 同一ファイルシステム内の移動であれば、通常は ACL や拡張属性もそのまま維持されます。
- **rsync (同期)**:
    - `# rsync -A <元> <先>` : **ACL** を保持して同期します。
    - `# rsync -X <元> <先>` : **拡張属性** を保持して同期します。
- **tar (アーカイブ)**:
    - `# tar --acls -cvf backup.tar <対象>` : ACL を含めてアーカイブを作成します。
    - `# tar --xattrs -cvf backup.tar <対象>` : 拡張属性を含めてアーカイブを作成します。

これらのコマンドは、特に **NFSv4 や Samba** といったネットワークファイル共有環境において、Linux 側とクライアント（Windows 等）側の権限不整合を防ぐために正しく使い分けることが求められます。
