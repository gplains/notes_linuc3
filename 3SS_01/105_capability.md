# 105 Linux Capabilities による権限制御

## ライフサイクルを想定したコマンド

### 1. 設定と確認 (File Capabilities)

バイナリファイルに対して、実行時に特定の特権を持たせるための操作です。

- **getcap (確認)**:
    - `$ getcap <ファイル名>` : ファイルに設定されているケーパビリティを表示します。
    - 例: `$ getcap /usr/bin/ping`
- **setcap (設定・削除)**:
    - `# setcap <ケーパビリティ>=<フラグ> <ファイル名>` : ファイルに権限を付与します。
    - **フラグの種類**: `e` (Effective: 有効)、`p` (Permitted: 許可)、`i` (Inheritable: 継承)。
    - **設定例**: `# setcap cap_net_raw+ep /usr/bin/ping` （ping に RAW ソケットの使用を許可）。
    - **削除例**: `# setcap -r <ファイル名>` : ファイルからすべてのケーパビリティを削除します。

### 2. プロセス状態の調査とデバッグ

実行中のプロセスや現在のシェルが持つ権限を確認します。

- **capsh (デコードとデバッグ)**:
    - `$ capsh --decode=<16進数値>` : `/proc/<PID>/status` などに含まれる 16 進数のケーパビリティビットを人間が読める形式に変換します。
    - `$ capsh --print` : 現在のシェルが持つケーパビリティセットを表示します。
- **getpcaps (外部ソース情報)**:
    - `$ getpcaps <PID>` : 実行中の特定のプロセス ID が持つケーパビリティを確認する際に使用されます。

### 3. systemd によるサービス制御 (Execution Control)

systemd ユニットファイルを使用して、サービスプロセスが使用できる権限を制限（サンドボックス化）します。

- **設定パラメータ**:
    - **`CapabilityBoundingSet=`**: プロセスが取得可能なケーパビリティの**上限**を定義します。ここに指定しなかった権限は、プロセスが root で実行されていても使用できなくなります。
    - **`AmbientCapabilities=`**: 非特権ユーザーとして実行されるプロセスに対し、特定のケーパビリティを保持したまま起動させたい場合に使用します。
    - **`NoNewPrivileges=yes`**: `execve()` システムコールを通じて、子プロセスが親プロセス以上の権限（setuid ビットなどによる昇格）を取得することを禁止します。

### 4. コンテナ環境での利用 (Podman)

Podman コンテナを実行する際、セキュリティ向上のために不要な権限を削ぎ落としたり、必要な権限のみを追加したりします。

- **podman run (権限の追加・削除)**:
    - `# podman run --cap-add <CAP_NAME>` : コンテナに特定の権限を追加します。
    - **例**: `# podman run -d --cap-add SYS_TIME ntpd` （時刻同期のために `CAP_SYS_TIME` を追加）。
    - `# podman run --cap-drop ALL` : いったんすべての権限を剥奪し、その後 `--cap-add` で必要なものだけを最小限追加する手法（最小権限の原則）が推奨されます。

### まとめ：主要な Capabilities と用途

試験対策として、以下の主要な種類と用途を把握しておくことが重要です。

|ケーパビリティ名|許可される主な操作|
|:--|:--|
|**`CAP_NET_BIND_SERVICE`**|1024 未満の特権ポートへのバインド|
|**`CAP_NET_RAW`**|RAW ソケットの使用（ping 等）|
|**`CAP_SYS_ADMIN`**|システム管理全般（非常に強力なため注意が必要）|
|**`CAP_SYS_TIME`**|システムクロックの変更|
|**`CAP_DAC_OVERRIDE`**|ファイルの読み書き実行権限（DAC）のバイパス|
|**`CAP_SYS_MODULE`**|カーネルモジュールのロード・アンロード|
